# 对接方案：把"豆包的能力"接进 VS Code

> 目标：做一个体验对标 **腾讯云 CodeBuddy** 的 VS Code 扩展——侧边栏 Agent 对话、行内补全、行内改写、
> 工作区工具调用、MCP、以及与豆包桌面端的双向交接。
> 本文回答一个问题：**每一块能力从哪里来、怎么接、代价是什么。**

---

## 1. 先把"豆包的功能"拆成三类

分析后可以确认，豆包桌面端（2.36.10）的能力分布在三个完全不同的层（见 `02-架构与实现.md` §3）：

| 能力类别 | 载体 | 能否被第三方复用 | 我们的接法 |
|---|---|---|---|
| **A. 模型能力**（对话、代码生成、推理、视觉） | 远端服务（Web HTTPS） | ✅ 官方 Ark API 等价开放 | `chat/completions`（OpenAI 兼容） |
| **B. 工具/执行能力**（读写文件、跑命令、快照、终端） | 本地原生（MCP / ConPTY / Python） | ✅ MCP 是公开协议 | 我们**自己实现**一套，并**导出为 MCP Server** 给豆包用 |
| **C. 产品闭环**（会话、分享、登录态、Agent UI） | 私有 Web + `metasecml` 风控 | ❌ 重放不可持续 | 不做；用深链把人送回豆包 |

**核心判断**：A 走官方 API、B 自己做并且反过来喂给豆包、C 只做深链跳转。这样三块都不需要技术调研私有协议。

## 2. 能力 ↔ 实现对照表（对标 CodeBuddy）

| CodeBuddy / Cursor 的能力 | 本扩展实现 | 依赖 |
|---|---|---|

## 2.5 路线 A′：桌面端登录态直连（免 API Key，推荐个人使用）

**为什么不"直连远端 web"**：豆包网页接口只认它自己的客户端（会话 Cookie + `msToken`/`a_bogus`
签名 + `metasecml`/`bdticket` 设备指纹）。自己造一个 HTTP 客户端去调它 = 技术调研签名 + 长期对抗风控；
而 CodeBuddy 能直连，是因为腾讯给 IDE 产品开了官方后端。豆包没有这个口子。

**替代思路**：把**已经登录的官方客户端**当成后端。

```
VS Code 扩展 ──CDP(127.0.0.1:9222)──▶ 豆包桌面端（Chromium 147，已登录）
   写 [data-testid=chat_input_input]   ·  点 [chat_input_send_button]
   ◀── 轮询 [data-testid=receive_message] 的 [message_text_content]
        （data-streaming=true/false 就是生成中/结束信号）
```

- 登录态、签名、风控：全部由官方客户端完成，扩展**不接触 Cookie/凭据**。
- 实测：`loggedIn=true`，写入 → 发送 → 流式读回 C/Python/JS 代码块均成功（详见 `docs/04`）。
- 代价：要开着豆包；发送前会 `Page.bringToFront`（抢一次焦点）；依赖页面 `data-testid`（非公开契约）；
  **没有工具调用**（改由 MCP 反向提供）；**行内补全不可用**（官方不开放 FIM）。
- 启用：命令「豆包: 以调试端口启动桌面端」→ 侧边栏直接对话；`doubao.authMode` 默认就是 `desktop`。

> 两个模式可以并存：对话走桌面端（免 Key），补全/Agent 工具走 Ark（有 Key 时）。

## 3. 路线 A：模型能力（火山方舟 Ark）

### 3.1 端点与密钥

```bash
# 通用按量
https://ark.cn-beijing.volces.com/api/v3
# Coding Plan 订阅（走套餐额度，价格更友好；不要和上面混用同一个 key 路径）
https://ark.cn-beijing.volces.com/api/coding/v3
```

- 鉴权：`Authorization: Bearer $ARK_API_KEY`
- Key 获取：火山引擎控制台 → 方舟 → API Key 管理
- 模型 ID 示例：`doubao-seed-code`、`doubao-seed-2.0-code`、`doubao-seed-2.0-pro`、`doubao-seed-1-6-*`
  （**以控制台"开通管理"里实际可用的 ID 为准**，各账号/区域略有差异）

> 说明：以上端点/模型名来自公开资料与厂商文档摘要，属于"可配置默认值"，
> 扩展里全部通过 `doubao.baseUrl` / `doubao.model` 覆盖，不硬编码。

### 3.2 请求契约（扩展实际发出的报文）

```http
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json

{
  "model": "doubao-seed-code",
  "stream": true,
  "temperature": 0.3,
  "max_tokens": 8192,
  "messages": [
    {"role": "system", "content": "<项目规则 + 工具使用规范>"},
    {"role": "user",   "content": "<选区/文件内容 + 用户问题>"}
  ],
  "tools": [
    {"type": "function", "function": {
      "name": "read_file",
      "description": "读取工作区内文件（支持行范围）",
      "parameters": {"type": "object",
        "properties": {"path": {"type":"string"}, "start":{"type":"integer"}, "end":{"type":"integer"}},
        "required": ["path"]}}}
  ],
  "tool_choice": "auto"
}
```

流式响应（SSE，每行 `data: {...}`，以 `data: [DONE]` 结束）：

```
data: {"choices":[{"delta":{"content":"好的"}}]}
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"id":"call_1","function":{"name":"read_file","arguments":"{\"path\":"}}]}}]}
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"\"src/a.ts\"}"}}]}}]}
data: [DONE]
```

关键实现点（`ark/client.ts`）：
1. `tool_calls` 是**增量拼接**的：按 `index` 累积 `arguments` 字符串，流结束再 `JSON.parse`（要容错）。
2. 必须支持 `AbortController`（用户点"停止"/切换会话时立刻断开）。
3. 错误要把 `status` + body 前 500 字符带回 UI（401=key 错、404=模型/路径错、429=限流）。

### 3.3 Agent 循环（`agent/loop.ts`）

```
用户消息
  └→ POST /chat/completions (tools)
       ├─ 若返回 content       → 流式渲染给用户
       └─ 若返回 tool_calls    → 逐个执行工具 → 结果以 role:"tool" 追加 → 再请求
                                   （最多 maxToolIterations 轮，默认 12）
```

工具结果**必须截断**（默认 8000 字符）并带"已截断"标记，否则长文件会把上下文打爆。

### 3.4 行内补全（FIM）

两种模式，按模型能力自动降级：

| 模式 | 请求 | 适用 |
|---|---|---|
| `fim` | `POST {base}/completions` `{model, prompt, suffix, max_tokens, stream:false}` | 支持 FIM 的代码模型（`doubao-seed-code`） |
| `chat` | 用 chat 接口，把前文放 user、要求"只输出补全片段，不要解释" | 任意 chat 模型兜底 |

工程细节：300 ms 防抖、`CancellationToken` 早退、取光标前 4 KB / 后 1 KB、同一位置 2 s 内缓存、
补全结果做"与后文重复"裁剪（避免重复行）。

## 4. 路线 B：把编辑器变成豆包可调用的 MCP Server

### 4.1 为什么这条是"官方设计内"的

`mcp_helper.dll` 的字符串取证（`tools/mcpstr.py`）已经非常明确：

```
rmcp-3.2.0/src/transport/streamable_http_client.rs
rmcp-3.2.0/src/transport/worker.rs
STDIO MCP initialize failed / timed out
tools/list failed / tools/call total timeout / resources/read
MCP session transport closed / accepted connector lifecycle
MCP_PROTOCOL / TRANSPORT_UNAVAILABLE / MCP_CAPABILITY_UNAVAILABLE
Dola MCP
```

即豆包桌面端内置了一个 **Rust `rmcp` MCP 客户端**，支持 **stdio / Streamable HTTP / 旧版 HTTP+SSE**，
还实现了 OAuth 与 `resources/read`、**MCP Apps**（`MCP_APPS_UNAVAILABLE`）。

### 4.2 我们的 Server 设计（`src/mcp/server.ts`）

```
stdin/stdout (JSON-RPC 2.0, 一行一条消息)
  initialize               → { protocolVersion, capabilities:{tools:{listChanged:false}}, serverInfo, instructions }
  notifications/initialized
  tools/list               → 5 个工具（见下表，实测输出）
  tools/call               → { content:[{type:"text",text}], isError }
```

暴露的工具（实测 `tools/list` 返回；全部限制在根目录内，`realpath` + 相对路径判定防穿越）：

| 工具 | 参数 | 说明 |
|---|---|---|
| `read_file` | `path`, `start_line?`, `end_line?` | 带行号返回 |
| `list_dir` | `path?`, `recursive?` | 目录浏览，跳过噪音目录 |
| `grep` | `pattern`, `path?`, `max_results?` | 正则搜索，返回 `文件:行号:内容` |
| `write_file` | `path`, `content` | 创建/覆盖，返回摘要 |
| `run_shell` | `command`, `cwd?` | 同步执行，最长 60 s；默认 **关闭**，需显式 `--allow-exec` 启动 |

> 扩展内向 Agent 暴露的工具是另一组 7 个（多了 `apply_patch` / `run_terminal` / `get_diagnostics`），
> 因为它们依赖 VS Code API（`WorkspaceEdit`、诊断、模态确认），不能脱离宿主进程运行。

启动示例（用户在豆包"MCP 连接器/MCP 服务器"里填）：

```json
{
  "mcpServers": {
    "vscode-workspace": {
      "command": "node",
      "args": ["D:\\rex86\\doubao-re\\extension\\doubao-coder\\out\\mcp\\server.js"],
      "env": { "DC_WORKSPACE": "${workspaceFolder}" }
    }
  }
}
```

### 4.3 另一方向：我们也能当 MCP Client

同一份协议，扩展也可以连别人的 MCP（GitHub、数据库、浏览器…），把 `tools/list` 合并进
Agent 的工具表。`agent/tools.ts` 里预留了 `externalTools` 合并点。

## 5. 路线 C：深链交接（`doubao://`）

已确认的注册项：

```
HKCU\Software\Classes\doubao
  (Default)        = URL:doubao
  URL Protocol     = ""
  DefaultIcon      = "...\DoubaoLinkRouter.exe",0
  shell\open\command = "...\DoubaoLinkRouter.exe" --single-argument %1
```

`DoubaoLinkRouter.exe` 内可见的 URL 形态与错误码：

```
doubao://doubaoapp/active-chat
preferred_clientdoubao / doubaowork / doubaoworkapp
url=   invalid_url   invalid_inner_url   unsupported_url
doubao_state / doubaowork_state / no_available_prod…
```

因此扩展里做"尽力而为"的交接：

```ts
// 1) 首选：把问题 + 文件引用塞进 query
const url = `doubao://doubaoapp/active-chat?url=${encodeURIComponent(prompt)}`;
await vscode.env.openExternal(vscode.Uri.parse(url));

// 2) 降级：写剪贴板 + 提示"已复制，去豆包里粘贴"
await vscode.env.clipboard.writeText(prompt);
```

> 因为 query 参数集合未公开，**不要**把关键流程建立在深链上；它只是"锦上添花"的人机切换。
> 也不要假设 `doubao://` 一定被注册（未安装客户端的机器上会抛错，需 catch）。

## 6. 明确不做的三件事（以及原因）

| 不做 | 原因 |
|---|---|
| 重放 `www.doubao.com` 的私有 HTTPS 接口（自己算 `a_bogus`/`msToken`） | 需要 `metasecml`/`bdticket` 设备指纹配合；客户端一更新就失效；违反用户协议；账号有风控风险 |
| 注入/劫持 `Doubao.exe` 进程（DLL 注入、改内存、改签名） | 触发签名校验与反调试；分发即侵权 |
| 复用 `liblark.dll` / `mcp_helper.dll` 的内部 ABI | 导出面只有 `saman_mcp_helper_run` 这类未文档化入口，与版本强绑定（如 `saman_mcp_helper_abi_version`），不可维护 |
| 导出/复用豆包的 Cookie、登录凭据、设备指纹 | 那才是真正的"盗用登录态"；本方案从头到尾不碰这些文件 |

**合规底线**：不绕过鉴权、不绕过鉴权、不伪造签名、不批量抓取、不内置任何豆包客户端的密钥/证书/设备标识。
路线 A′ 用的是**你自己的账号 + 官方客户端 + 官方页面**，只是把"人手动点"换成"协议驱动"。

## 7. 决策树：用户想要什么 → 用哪条路

```
用户："我要在 VS Code 里用豆包写代码"
 ├─ 不想申请 Key，只想用已登录的豆包账号
 │    ├─ 要"在侧边栏直接聊、流式出代码" ────────→ 路线 A′（CDP 驱动桌面端，免 Key）★默认
 │    └─ 要"豆包能读写我的工程" ────────────────→ 路线 B（MCP Server 挂进豆包）
 └─ 有/能申请 火山方舟 API Key ─────────────────→ 路线 A（Chat + Agent 工具 + 行内补全，最稳）
       （也可以 A′ 负责对话、A 负责补全，两者并存）

用户："我要在豆包里用我的企业 MCP / 数据库"
 └─ 扩展作为 MCP Client 聚合 → 同时自身可被豆包当 MCP Server（双向）
```

## 8. 落地检查清单

- [ ] `doubao.authMode` 默认 `desktop`；想用 Ark 的人切 `ark` 并配 Key
- [ ] Ark 模式下 `doubao.apiKey` 只存 `SecretStorage`（`context.secrets`），**不写 settings.json 明文**
- [ ] 桌面端模式下**不读取、不导出**任何 Cookie/凭据文件；只走 127.0.0.1 的 CDP
- [ ] 所有出网请求带 `AbortSignal` + 超时；CDP 调用逐条超时（避免页面卡死拖住扩展）
- [ ] 工具执行有"路径必须落在 workspace 内"的硬校验（`realpath` + `path.relative` 判定）
- [ ] `run_terminal` 默认关闭，开启需二次确认（模态对话框），并把命令原文写进日志
- [ ] 首次使用提示：Ark 模式会把代码片段发到火山方舟；桌面端模式会操作你正在用的豆包窗口
- [ ] 不做任何遥测；日志只落本地 OutputChannel，可一键清空
- [ ] README 明确写"非官方扩展，与字节跳动无隶属关系"
