# 15. 历史任务重构（新实现）

旧实现只读当前渲染的 5 条列表项，没点「展开更多」也没滚动，所以：
1. 豆包任务列表没同步全；2. 点击按 index 对不上。

## 新设计

### 收集（`src/bridge/desktop-history-all.ts`）
- 每轮：点「展开更多」→ 把 `chat_list_wrapper` 的可滚动祖先滚到底 → 等 350ms → 收集本轮渲染的
  `[data-testid="conversation-list-v2-item"]`，按 `data-conversation-id` 去重；
- 连续 3 轮没有新条目即停止（最多 60 轮），并回调 `正在同步豆包对话…（已 N 条）`；
- 实测：从 5 条涨到 **45 条**。

### 打开（同一模块 `openDesktopConversationById`）
- 按 `data-conversation-id` 精确找节点，必要时展开更多/滚动；
- `scrollIntoView` 后点击；
- 轮询 `location.href` 的 `/chat/<id>` 与 `[data-conversation-active="true"]` 的 id，**校验一致才算成功**；
- 不一致返回错误，不再“点了别的对话”。

### 两层对应
- 列表项自带 `id + title`；本地会话保存 `desktopId`；打开时优先 id，标题兜底；
- 失效项（id 不在列表中）标「对话已不存在」。

### 面板
- 历史面板加载时显示实时条数；
- 打开历史条目传 id，面板走 `openDesktopConversationById`。

## 验收
1. 打开历史面板能看到全部对话（含展开更多后的）；
2. 点任意条目切到对应 id 的对话；
3. 切换失败有明确提示，不会静默跳到别的对话；
4. 本地会话与豆包对话按 id 一一对应。
