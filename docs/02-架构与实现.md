## 1. 设计目标与非目标

**目标**（对齐 CodeBuddy 的核心 80%）

| # | 目标 | 验收标准 |
|---|---|---|
| G1 | 侧边栏对话，流式输出 | 首字节 < 1.5 s（取决于网络），中途可停止 |
| G2 | Agent 能自己读写多个文件 | 一次任务内 ≥ 2 轮工具调用来回 |
| G3 | 每次改动可看 diff、可撤销 | 命令「查看/撤销上一次改动」 |
| G4 | 行内补全不打扰 | 300 ms 防抖、拒绝时无副作用、缓存命中 < 5 ms |
| G5 | 行内改写有预览 | 不确认不落盘 |
| G6 | 能和豆包桌面端协作 | 深链投送 + MCP 反向驱动 |
| G7 | 不泄露代码 | 无遥测；Key 存 SecretStorage；只在用户提问时出网 |

**非目标**（本版明确不做）

- 向量索引 / RAG 知识库（只做 `grep` + 按需读文件）
- 多根工作区的高级路由（取活动编辑器所属根）
- 云端会话同步、团队协作、计费面板
- 兼容 VS Code < 1.90

## 3. 三条主数据流

### 3.1 对话 / Agent

```
用户输入 ──▶ panel.ask()
              ├─ prompt.buildSystemPrompt()           （内置提示 + rules.md）
              ├─ prompt.collectContext()              （当前文件 / 选区 / 诊断 / @文件）
              └─ AgentLoop.run(history, userContent, signal, system)
                    │
                    ├─ round 1: ArkClient.chatStream(messages, tools)
                    │      ├─ onTextDelta ──▶ postMessage(assistant_delta)
                    │      └─ tool_calls? ──▶ executeTool() ──▶ postMessage(tool_start/tool_end)
                    │                          └─ push {role:'tool', tool_call_id, content}
                    ├─ round 2..N 同上（≤ maxToolIterations，默认 8）
                    └─ onDone ──▶ postMessage(assistant_done)
```

要点：
- `tool_call_id` 必须与 assistant 的 `tool_calls[].id` 一一对应，否则 Ark 返回 400；
- 每轮把 assistant 消息（含 `tool_calls`）压入历史，模型才知道自己"刚才请求过什么"；
- 用户点"停止"→ `AbortController.abort()` → `ArkError.aborted=true` → 循环干净退出，不留半条消息。

### 3.1′ 对话（桌面端登录态，`authMode=desktop`，默认）

```
用户输入 ──▶ panel.handleUser()
              ├─ prompt.buildSystemPrompt() + buildUserContent()   （工作区上下文照旧注入）
              ├─ PTC 开启（默认）→ PtcAgent.run()
              │     ├─ 第 1 轮：prompt = 系统提示 + PTC 协议 + 工具目录 + 上下文 + 用户请求
              │     │     askDesktop(..., newChat=第一轮)
              │     ├─ 流式：visibleProse() 过滤掉 ```tool 块，只推正文
              │     ├─ parsePtc() → 有工具块 → executeTool()（7 个工具，同一套安全校验）
              │     ├─ 第 2..N 轮：把 <tool_result> 发回同一会话（newChat=false）
              │     └─ 没有工具块 → 结束（≤ doubao.ptc.maxRounds）
              └─ PTC 关闭 → askDesktop() 纯对话
```

底层（两种模式共用）：

```
bridge/desktop.askDesktop()
  ├─ listTargets(9222) → 找 doubao-chat 页面 → CdpSession
  ├─ MD_INSTALL_JS（注入 __dcMd，带版本号）
  ├─ 等 [chat_input_input] 就绪（最多 10 s）
  ├─ 可选：[create_conversation_button].click() + Ctrl+Shift+K 兜底，并校验消息数为 0
  ├─ focus + 全选删除 → Input.insertText(prompt) → 回读长度校验
  ├─ 记录基线（最后一条 receive_message 的文本 + data-streaming）
  ├─ Page.bringToFront → 点 [chat_input_send_button]（失败→回车）
  └─ 每 200 ms 读最后一条 receive_message
        ├─ 文本变化 → onDelta(增量) → webview
        └─ data-streaming=false 或 2.5 s 静止 → 结束
```

### 3.2 行内补全（仅 `authMode=ark`）

```
光标移动 ──▶ provider.provideInlineCompletionItems()
               ├─ 2 s 缓存命中？ → 直接返回
               ├─ setTimeout(300 ms)（新请求到来即 clearTimeout）
               ├─ token.isCancellationRequested 检查（两处：发请求前、返回前）
               ├─ 取前 4000 字符 / 后 1000 字符
               ├─ completeFIM(prompt, suffix)
               │    ├─ POST {base}/completions（支持 FIM 的代码模型）
               │    └─ 404/400 → 自动回退 completeViaChat()
               └─ sanitize：去 ``` 围栏、去重复尾行、限 40 行 / 2000 字
```

### 3.3 行内改写（Ctrl+Alt+I）
```
选区 + 指令 ──▶ inline/edit.ts
                  ├─ 无配置 → 引导设置 Key
                  ├─ Ark chat（非流式，温度更低）
                  ├─ 把结果写入虚拟文档 doubao-preview:
                  ├─ vscode.diff 打开「原文 ↔ 改写后」
                  ├─ 模态确认「应用 / 取消」
                  ├─ 应用：WorkspaceEdit.replace() + workspaceState 记录旧文本
                  └─ 「撤销上一次改动」：diff 再开 + 回滚
```

## 4. 工具协议（Agent 侧 7 个）

| 工具 | 参数（JSON Schema 摘要） | 副作用 | 安全控制 |
|---|---|---|---|
| `read_file` | `path`, `start_line?`, `end_line?` | 无 | 路径必须在根内；单次 ≤ 40000 字符 |
| `list_dir` | `path?`, `recursive?` | 无 | 跳过 `node_modules/.git/dist/out`；≤ 300 条 |
| `grep` | `pattern`, `path?`, `max_results?` | 无 | 单文件 ≤ 512 KB；结果 ≤ 50 条 |
| `write_file` | `path`, `content` | **写** | `requireTrusted()`；WorkspaceEdit；记旧文本 |
| `apply_patch` | `path`, `old_text`, `new_text` | **写** | 必须精确唯一匹配，否则报错（禁止模型猜） |
| `run_terminal` | `command`, `cwd?`, `timeout_ms?` | **执行** | 默认逐条模态确认；`autoRun=true` 才跳过；超时 ≤ 300 s |
| `get_diagnostics` | `path?` | 无 | 只读 VS Code 诊断集合 |

`apply_patch` 的"精确匹配"是刻意的设计：宁可让模型重读文件，也不要它把代码改错位。
（这是 Codex/Cursor 这类工具最常见的翻车点。）

## 5. 上下文预算

| 项 | 预算 | 策略 |
|---|---|---|
| 系统提示词 | ~1.5 KB | 固定模板 + `rules.md`（>8 KB 截断并提示） |
| 当前文件 | ≤ 40 KB 或全文（< 400 行） | 超限时只给"结构 + 光标附近" |
| 选区 | 原样 | 超过 20 KB 提示用户缩小选区 |
| 诊断 | ≤ 30 条 | 按严重级排序，`error` 优先 |
| 工具结果 | 8000 字符 | 统一 `truncate()`，带"原长 N"标记 |
| 历史 | 最近 40 条消息 | `trimHistory()` 并强制以 `user` 开头 |

| 方向 | `type` | 载荷 | 说明 |

| 扩展 → 前端 | `user` | `text, at` | 回显用户消息 |

所有资源走 `asWebviewUri`，**不引任何 CDN**（离线可用、无第三方追踪）。

## 7. 安全设计（五层）

1. **密钥**：`SecretStorage`（`doubao.setApiKey` 写入），settings 只是兼容入口；日志永不打印 Key（只打来源）。
2. **路径**：`resolveInsideRoot()` 拒绝 `..`，MCP 侧同样实现一遍（拒绝 `/etc/passwd`、`..\..`）。
3. **写入**：只走 `WorkspaceEdit`，先存旧文本再改；不可信工作区（Restricted Mode）直接拒绝写与执行。
4. **执行**：`run_terminal` 默认模态确认，展示完整命令与 cwd；MCP 的 `run_shell` 需显式 `--allow-exec`。
5. **出网**：只有 Ark 域名；无遥测、无自动上报；失败信息只回显 `status + body.slice(0,500)`。

## 10. 已知限制

1. **桌面端模式依赖页面结构**：`data-testid` 是官方测试钩子（非公开契约），豆包大版本更新后可能要重新核对；
   用 `tools/cdp_inspect*.py` 可一键重新取证。
2. **桌面端模式会操作你正在用的窗口**：发送前 `Page.bringToFront`（避免后台节流）会抢一次焦点；
   回复写进你当前会话（或 `desktop.newChat=true` 新开一个）。
3. **桌面端模式无行内补全**：官方不开放 FIM；补全需要 `authMode=ark`。
   （工具调用已由 **PTC** 补上，见 `04-PTC模式.md`。）
4. **未做真实 Ark 联调**：无 Key，Ark 路径的在线验证待补；已有 mock 覆盖。
5. **改动停留在缓冲区**：写入不自动 `save()`，`run_terminal` 里的编译读的是磁盘旧内容——需要用户先保存。
6. **无索引**：大仓库靠 `grep` + 按需读文件，跨文件理解能力弱于带 RAG 的产品。
7. **VS Code 不能直接消费 stdio MCP**：`out/mcp/server.js` 是给豆包等外部宿主用的；扩展自身的工具是原生注册的。
8. **深链参数非官方文档化**：`doubao://doubaoapp/active-chat?url=…` 属"尽力而为"，已做异常捕获与剪贴板兜底。
