# 「本地电脑」能力：对照豆包安装目录的移植说明

> 你问的是"照着截图自己写的，还是参考移植的"。
> **这一版是参考移植**：先让子 agent 逐行读了豆包安装目录里的官方实现
> （`task-mode-resource/python-packages/gac_runtime/**`），产出带 `文件:行号` 的规格，
> 再按规格一比一落到 TypeScript。本文给出**对照表 + 实测证据 + 差异说明**。
>
> 同时按你的要求：**凡是依赖本地资源的能力，先确认装了豆包、并直接用安装目录里的资源**。

---

## 1. 官方实现长什么样（先纠正三个常见误解）

| 误解 | 事实（带证据） |
|---|---|
| "本地电脑 = 直接调 Win32" | 不是。Python SDK 只是**门面**，实际走 **GAC 命令通道**：named pipe + ChaCha20-Poly1305 帧，18 个命令号（`wire.py:157-206`、`transport/protocol.py:53-146`、`modules/computer_use_windows.py:143-328`） |
| "点击靠元素引用/AX 树" | Windows 通道是**纯坐标 0–1000 归一化**，没有 ref；AX 树只在 macOS 通道（`_validation.py:33-49`、`computer_use_ax/services/api.py:385-416`） |
| "有个任务状态机负责 plan/act/observe" | Python 侧**没有**循环。`cell.py` 只执行"一次动作批 + 记账 + 渲染"，plan/act 的驱动在宿主（`cell.py:373-374`、`runner.py:146-147`） |

所以"移植"正确的落点是：**动作面 + 线协议 + envelope 渲染 + cell 记账**，
再自己补宿主侧的循环（我们已经有的 `agent/task.ts`）。

## 2. 结构对照表

| 官方实现 | 本扩展（TS） | 移植程度 |
|---|---|---|
| `wire.py:157-206`（命令 envelope） | `src/cu/wire.ts` `encodeCommand/decodeCommand` | 位序一致：`u8 ver | u8 module | u32 LE cmd | u32 LE len | JSON` |
| `transport/protocol.py:53-146`（GACF 帧） | `src/cu/wire.ts` `encodeFrame/decodeFrame` | 一致：`"GACF" + u32 LE size`；`MAX_FRAME_SIZE=128MiB`、握手 4096 |
| `modules/computer_use_windows.py:347-388`（截图响应） | `decodeScreenshotResponse` | 一致：JSON + `u32 w | u32 h | u32 png_size | png`，**双份尺寸互校验 + IHDR 大端再校验** |
| `modules/computer_use_windows.py:143-328`（18 命令号） | `wire.ts` `Command` | 一致（1,2,3,5..18，无 4） |
| `computer_use/_windows/public/api.py:63-84`（20 动作） | `src/cu/actions.ts` `ComputerUse` | 名称/参数/校验怪癖全对齐（见 §3） |
| `cell.py`（CellExecutor 记账） | `src/cu/cell.ts` | 一致：`attempted→completed/rejected`、图像淘汰**级联删观察**、`type` 只记 `chars=N`、hotkey 只留 8 键 |
| `envelope.py`（渲染） | `src/cu/envelope.ts` | 一致：`[result status=…]`/`[progress confirmed=… possible=…]`/`[obs scope=…]`/`[truncated …]`/`[next] READY`、6 种状态判定、稳定码正则 |
| `gac_profile.py:65-79`（12 个预算） | `src/cu/profile.ts` | 常量逐个抄；"一 cell 一 profile、冲突报 `BU_GAC_PROFILE_CONFLICT`" |
| `transport/{handshake,named_pipe,chacha20poly1305}.py` | **未移植** | 需要宿主 secret/session，外部进程无法加入（见 §5） |
| `browser_use` / `computer_use_ax` | **未移植** | 本次只做 Windows 本地电脑；AX 是 macOS 通道 |

## 3. 动作面（20 个）与**必须保留的怪癖**

| 动作 | 参数 | 移植时**不能顺手改**的点 |
|---|---|---|
| `screenshot` | `tag?`, `show?=true` | 返回**整块虚拟桌面 PNG**；`show` 只影响是否进观察，**不进报文** |
| `switch_desktop` | `desktop` ∈ {main, pip} | 其它值必须报 `CU_INVALID_ACTION`；`pip` 是宿主私有桌面，本移植直接报错（stub） |
| `list_apps` / `launch_app` | `name` | `launch_app` 返回 `{app,status,launch_method}` 两套枚举 |
| `click` / `left_double` / `triple_click` / `right_single` | `x,y` | 按钮与点击次数**不可配**，由动作名决定 |
| `hover` / `drag` / `scroll` | `drag(x1,y1,x2,y2)`；`scroll(x,y,delta)` | `delta` 数字 ±1..10 四舍五入；别名 `up/down/left/right` = ±5，`left/right` 自动横向 |
| `type` | `text` | 空串**直接返回不发动作** |
| `hotkey` | `*keys` | 必须逐键传；某个键含 `+` → `CU_BAD_HOTKEY` |
| `press` / `key_down` / `key_up` | `key` | 键名小写 + 4 别名（control→ctrl、escape→esc、return→enter、del→delete） |
| `wait` | `seconds=3` | **纯本地 sleep**，不记动作、不碰通道；范围 [0,180] |
| `get_clipboard` / `set_clipboard` / `copy_selection` | `text` | `copy_selection` = Ctrl+C 后读剪贴板 |
| **坐标** | `x,y` | `coordinate()` **只校验有限数字、不 clamp**（`_validation.py:33-49`）——照抄了，单测里有专门一条 |

单测覆盖：`test/cu-core.test.js`（**54 条**，含帧往返、截图响应双份校验、状态映射、截断算法、坐标不 clamp、scroll 别名、hotkey 报错、type 脱敏、图像级联淘汰、superseded）。

## 4. 安装检测与资源复用（你这次的重点）

```
启动 / 用到本地电脑能力
   │
   ├─ detectInstall()  探测 %LOCALAPPDATA%\Doubao\Application\app\Doubao.exe（或配置的 installPath）
   │     ├─ 找到 → 读 清单文件（版本/渠道）+ 检查 gac_runtime / terminal_conpty / mcp_helper / runtime 组件
   │     └─ 没找到 → requireInstall()：**弹模态窗**说明需要安装豆包、
   │                列出将复用哪些资源 → 「打开下载页 / 重新检测」
   │
   ├─ readComputerUseSurface()  用安装目录里的 SDK + 本机 Python，
   │      import seed_computer_use → 读出 20 个动作名 + **真实签名** + docstring
   │      （= 我们的工具描述从"官方安装目录"生成，不是手写常量）
   │
   └─ selectBackend()
         ├─ probeGacChannel() 可用 → DoubaoSdkBackend（真的调安装目录里的 SDK）
```

命令：

- **`豆包: 检测豆包安装与本地资源`** —— 打印安装目录/版本/SDK 路径/GAC 通道状态/最终用哪个后端；
- **`豆包: 设置安装路径`** —— 手动指定 `Doubao.exe`（写 `doubao.installPath`）；
- 配置：`doubao.installPath`、`doubao.pythonPath`（默认 `python`）、`doubao.computer.backend`（`auto|doubao|win32`）。

## 5. 一个必须说清楚的硬约束

官方 SDK **只能被豆包拉起的进程使用**：它依赖宿主注入的 GAC 环境变量（`CUA_GAC_SERVER_PORT`/`CUA_GAC_SECRET`/session id）。
本机实测（在 VSCode/终端里直接调）：

```
RuntimeError: GUI as Coding is not available: missing CUA_GAC_SERVER_PORT
```

所以本移植的策略是**诚实降级**，而不是假装接上了：

| 场景 | 行为 |
|---|---|
| 豆包已装 + 有 GAC 通道（如被豆包拉起） | 用安装目录里的官方 SDK 执行（`DoubaoSdkBackend`） |
| 豆包已装 + 无 GAC 通道 | 用本地 Win32 后端（`SendInput` + `System.Drawing`），日志与诊断命令里写明原因 |
| 豆包没装 | 弹安装引导；本地电脑相关功能不可用 |

Win32 后端实测（`test/cu-win32.test.js`，**6 条全 PASS**）：

```
截图：2048x1152, 152 KB, 259ms（整块虚拟桌面）
```

## 6. 与官方实现的已知差异

| 差异 | 原因 | 影响 |
|---|---|---|
| 没有 GAC 加密管道（ChaCha20-Poly1305 / 握手 v1/v2） | 需要宿主 secret，外部无法加入 | 只影响"寄生在豆包进程里"的场景，不影响功能面 |
| 没有 AX 树 / 元素引用 | 那是 macOS 通道 | Windows 上本来就只有截图 |
| `switch_desktop('pip')` 直接报错 | pip 是宿主的会话桌面，无公开 API | 与原实现"只接受 main/pip、且 pip 仅在宿主内可用"一致 |
| 动作执行用 PowerShell + SendInput，不是宿主原生 | 无 GAC 权限 | 首次调用多 ~250–350 ms（PowerShell 启动 + Add-Type） |
| 没有 `debug_trace.py` 的 JSONL 链路 | 调试设施 | 用扩展自己的 OutputChannel 代替 |

## 7. 怎么验

```powershell
cd D:\rex86\doubao-re\extension\doubao-coder
node node_modules/typescript/bin/tsc -p .

node test/cu-core.test.js                     # 54 条：协议/渲染/校验/记账
```
