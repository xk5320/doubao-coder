# 任务模式：把"本地执行面"跑起来

> 对应命令：**`豆包: 任务模式：让豆包在本机执行任务`**
> 代码：`src/agent/task.ts`（循环）、`src/agent/policy.ts`（风险与确认）、`src/agent/tools.ts`（执行）

---

## 1. 它解决什么

普通对话是"一问一答"；任务模式是"**给个目标，让它自己一步步做完**"：

```
目标（如：把 src/util.ts 的回调改成 async/await 并跑 tsc 验证）
  ├─ ① 规划：模型给出 3–6 步计划
  ├─ ② 每轮：模型输出**一个** ```tool 动作（复用 PTC 文本协议）
  ├─ ③ 过闸：policy 判风险 → 按「始终询问 / 按需确认 / 全部允许」决定是否弹确认
  ├─ ④ 执行：复用 7 个工具（读/写/替换/搜索/终端/诊断）
  └─ ⑤ 回灌：把结果喂回同一会话，继续下一步；没动作了就输出最终答复
```

通道无关：桌面端（免 Key）走 `askDesktop`，Ark 走 `chatStream`，都只是 `complete(prompt) => string`。

## 2. 三档确认（对齐豆包「本地电脑」的措辞）

| 配置 | 语义 | 行为 |
|---|---|---|
| `ask`（始终询问） | 任何有副作用的操作都问 | 写文件/跑命令/危险命令全弹模态 |
| **`risk`（按需确认，默认）** | 只对高风险问 | 只读自动过；`git push`/`rm -rf`/`curl\|sh`/改注册表/关机等弹窗 |
| `allow`（全部允许） | 不弹 | 仍写日志；**慎用** |

风险分级（`policy.ts`）：

- **safe**：`read_file` / `list_dir` / `grep` / `get_diagnostics`；`dir`、`git status` 这类只读命令
- **risky**：写工作区内文件、`npm install`、`git commit`、`python build.py`、重定向覆盖、访问网络
- **dangerous**：`git push`（含 `--force`）、`rm -rf`、`del /s`、`format`、`shutdown`、`reg add`、`sc create`、
  `curl … | sh`、`iwr … | iex`、`set-executionpolicy`、`taskkill`、`diskpart`、`chmod 777`、`sudo`、写工作区外文件

被拒绝时**不会执行**，拒绝原因会作为工具结果回灌给模型，让它换方案。

## 3. 实测

离线单测：

- `test/policy.test.js` **20/20 PASS**（命令/工具分级、三档确认、拒绝路径）
- `test/task.test.js` **14/14 PASS**（计划解析、单动作执行、危险动作被拒且不执行、调用次数与事件顺序）

真机（桌面端通道，免 Key）：

```
[计划] 读取 README.md 前40行 / 提取核心信息 / 提炼两句总结 / 输出
[tool_start] read_file {"path":"README.md"}     ← 参数别名归一化后成功
[tool_end]   read_file ok=true
答复：该仓库用于豆包桌面端 Doubao.exe 的技术调研……同时提供一套可编译的 VS Code 扩展工程……
{"plan":[…4 步…],"steps":[{"tool":"read_file","ok":true,"risk":"safe"}],"elapsedMs":15357}
```

> 第一次真机跑时模型把参数写成 `file_path`（OpenAI 风格），工具报错 → 这一版加了
> `normalizeToolArgs()`（`file_path→path`、`old_string→old_text`、`cmd→command`…），
> 并在 PTC 提示里明确"Windows 用 PowerShell 等价命令，不要用 head/grep"。

## 4. 与「本地电脑」移植的关系

| 层 | 谁负责 |
|---|---|
| 计划 / 决策 / 何时停 | `task.ts`（我们自己，官方 Python 侧也没有这层） |
| 动作执行（文件/终端） | `tools.ts`（VS Code 原生能力） |
| 屏幕级动作（截屏/点击/输入） | `src/cu/**`（对照安装目录移植，见 `docs/07`） |
| 风险与确认 | `policy.ts`（官方 Python 侧没有，属宿主职责） |

也就是说：**任务模式 = 宿主循环 + 两套执行面**（编辑器面 + 屏幕面），
屏幕面那套是照着豆包安装目录里的实现移植的。

## 5. 配置

```jsonc
{
  "doubao.task.permission": "risk",   // ask | risk | allow
  "doubao.task.maxSteps": 10,          // 每步一次模型决策 + 一次工具执行
  "doubao.ptc.maxRounds": 4            // 普通 PTC 对话的轮数上限（与任务模式独立）
}
```

> 桌面端通道下，**每一轮都会在你豆包会话里多一条消息**；任务模式默认 10 步，
> 建议配 `doubao.desktop.newChat: true` 让任务跑在新会话里。
