# 12 · 对话区状态清单与「一次性复刻」计划

> 目标：不再"你发现一个我修一个"，而是**先把豆包对话区的状态枚举干净**，逐个对照我们有没有实现，
> 用清单驱动复刻，最后用自动化回归锁住。

---

## 0. 为什么之前总是"漏一个修一个"

| 原因 | 表现 |
|---|---|
| 靠肉眼发现 | 你没截图到就永远不知道有这状态 |
| 靠文本猜状态 | `正在执行代码` 不在 `message_text_content` 里 → 判断永远 false |
| 函数被删但调用还在 | `renderNativeBlocks` 丢失 → 整类状态静默消失 |
| 没有回归 | 修好一次，下次重构又丢 |

所以方法要换成：**枚举 → 对照 → 复刻 → 断言**。

## 3. 复刻执行计划

### P1 补齐缺失状态（本轮做）

| 项 | 做法 | 预估 |
|---|---|---|
| #14 展开全部/收起 | 正文超 12 行或 > 800 字 → 折叠 + 「展开全部」；状态块同理 | 1h |
| #16 代码块复制按钮 | `.ast-code` 右上角悬浮「复制」，`copyText()` | 0.5h |
| #15 操作条补齐 | 加「分享」（复制 Markdown）、「赞/踩」留空位（无接口） | 0.5h |
| #20 错误态统一样式 | `error` 消息渲染为带图标的红色卡片 | 0.5h |
| #13 工具结果折叠 | `</> 命令` 行可点开看输出 | 0.5h |

### P2 精度对齐（下一轮）

| 项 | 做法 |
|---|---|
| #5 标题字号 | 从页面量 h1–h4 的 size/weight，逐级写死比例 |
| #8/#9 代码度量 | 量代码块 padding/圆角/字号、行内 code 的 padding |
| #18 图片点击 | 点击缩略图 → 打开原图（webview 内预览层） |

### P3 锁住不回归（每轮必跑）

1. **状态快照**：`tools/snapshot_states.py` 抓 `ui-states.json`（已有雏形）
2. **渲染断言**：`test/ui-states.test.js` 把 24 类状态各造一个 fixture，喂给 `chat.js`，断言 DOM 出现对应节点
3. **函数存在性断言**：`renderAst / renderNativeBlocks / echoUserMessage / showPending …` 缺一个就 fail

> 第三条是血泪教训：这次「代码行不显示」就是函数被删、调用还在，语法检查完全查不出来。
